# てくてく、さんぽ

東京駅から行ける山と、その登山ルート・縦走ルート、自分の山行記録をまとめたサイトです。

## フォルダの中身

| ファイル | 中身 |
|---|---|
| `index.html` | ページの骨組み |
| `assets/style.css` | 見た目（色・レイアウト） |
| `assets/app.js` | 画面の動き（ふだんはさわらなくてよい） |
| `assets/mascot.png` | キャラクター画像（置くと自動で表示。なくても動く） |
| `data/config.js` | 設定（Google フォームの URL、記録を出すまでの日数など） |
| `data/mountains.js` | 山のデータ |
| `data/courses.js` | 登山ルートのデータ |
| `data/records.js` | 手で書く日記（ふだんは Google フォームを使う） |
| `data/memos.js` | てくてくメモ（山ごとの、自分の感想とアドバイス） |

`index.html` をダブルクリックすれば、パソコンで中身を見られます。
（YouTube の埋め込み再生とフォームの記録の読み込みは、ネットに公開したあとで動きます）

---

## サイトの役割

- 見る人：**自分自身** と **これから山に行く人**
- YAMAP は軌跡と写真、YouTube は動画、このサイトは **自分の言葉でまとめた感想と案内**
- さっと見て分かることを先に、長い感想は読みたい人だけが開く

| 書くもの | どこに | どう出るか |
|---|---|---|
| **てくてく日記** | Google フォーム | 1 回の山歩きごとの感想。一覧ではタイトルと冒頭だけ、押すと全文・動画・YAMAP が開く |
| **てくてくメモ** | `data/memos.js` | 山ごとの「ひとことで」「よかった」「気をつけて」「行き方のコツ」「ごはん・温泉」。山のカードのいちばん上に付せんのように出る |

日記はその日のこと、メモはその山のまとめ。メモは何回か登ったら書き足していく感じです。

### 日記へのリンク

日記を開くと、アドレスが `…/#diary/2025-05-19-takao` のようになります。
このリンクを YouTube の動画の説明欄に貼れば、動画を見た人が日記に来られます。（日記の画面の「リンクをコピー」でコピーできます）

## 日記をつける流れ

1. 山に登る → いつも通り **YAMAP** で記録
2. 動画を作ったら **YouTube** に上げる
3. スマホで **Google フォーム** に入力
4. 登った日から 3 日たつと、サイトに自動で表示される（日数は `data/config.js` で変更可）

### Google フォームの作り方（最初の 1 回だけ）

1. Google フォームを新しく作り、次の質問を **この名前のまま** 作る

   | 質問 | 形式 | 必須 |
   |---|---|---|
   | 登った日 | 日付 | ○ |
   | 山 | プルダウン（サイトの山の名前 ＋「その他」） | ○ |
   | タイトル | 記述式（例：鍋焼きうどんのために登った） | |
   | 感想 | 段落（長くて OK。最初の 2〜3 行が一覧に出る） | |
   | ルート | 記述式 | |
   | 行き方 | ラジオボタン（電車・バス / 車） | |
   | 天気 | ラジオボタン（晴れ / くもり / 雨 / 雪） | |
   | 歩いた時間 | 記述式（例 5:30） | |
   | YAMAPのURL | 記述式 | |
   | YouTubeのURL | 記述式 | |
   | サイトに載せる？ | ラジオボタン（はい / いいえ） | ○ |

2. 設定で **「メールアドレスを収集する」をオフ** にする
3. 「回答」タブ →「スプレッドシートにリンク」
4. スプレッドシートで **ファイル → 共有 → ウェブに公開** → 回答のシートを選び、形式を **CSV** にして公開
5. 出てきた URL を `data/config.js` の `recordsCsvUrl: ""` の `""` の中に貼る

> フォームの URL は人に教えないでください（誰でも書き込めてしまうため）。
> 「サイトに載せる？」が「いいえ」の記録は表示されません。

## 山やルートを足す

- 山：`data/mountains.js` に 1 行（1 ブロック）足す。書き方はファイルの先頭に説明があります
- ルート：`data/courses.js` に足す。`home` に山の `id` を書く
- 2 つ以上の山をつなぐ縦走は、`peaks:["jimba","takao"]` のように書くと、両方の山のカードに出ます
- 車の情報がわかったら、山かルートに `car:{time:"東京駅から約2時間", parking:"○○駐車場（無料・約50台）"}` を書く
- 新しい地方（甲信越・東北など）の山を足すと、絞り込みに自動で地方が増えます

## 公開のしくみ（GitHub ＋ Vercel）

- 公開中のサイト：https://tekuteku-sanpo.vercel.app/
- GitHub リポジトリ：https://github.com/paphoon/tekutesku （非公開）
- Vercel プロジェクト：`tekuteku-sanpo`

このフォルダの変更を GitHub の `main` に上げると、Vercel が自動でサイトを更新します（1 分ほど）。
更新するときは Claude に「GitHub に上げて」と頼めば OK です。自分で上げるときは、このフォルダで次を実行します。

```
git add -A
git commit -m "更新内容のメモ"
git push
```
`assets/style.css` や `assets/app.js` を変えたときは、`index.html` の中の `?v=3` の数字を 1 つ増やしてください（古い見た目が残るのを防ぎます）。

## 気をつけること

- 時間・距離・ルートは目安です。公開前と出かける前に、時刻表と登山情報を確認してください
- 出版社の本やサイトの文章・地図・写真は写さず、自分の言葉で書くかリンクにしてください
- 記録は日をずらして公開されます。GPX など位置のわかるものを載せるときは、自宅の近くが写っていないか確認してください
